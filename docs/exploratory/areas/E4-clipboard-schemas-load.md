## Seed seams (2026-07-29 mapping — starting points, not a ceiling)

- Paste does NOT regenerate connector-anchor ids: newConnectors map keeps `{...anchor}` with the original anchor.id, and anchor→anchor refs (ref.anchor) are never remapped through idMap. After paste, the view contains duplicate anchor ids across original+clone; validateView's anchorIds Set hides it (set membership passes), and any by-anchor-id operation (waypoint select/delete/drag) can hit the wrong connector.
- Load-time connector filter (useInitialDataManager ~line 102) only checks anchor→ITEM refs; a connector whose anchor references an ANCHOR of a dropped connector survives normalisation, then validateModel flags INVALID_ANCHOR_TO_ANCHOR_REF and the ENTIRE load fails with an error toast — one bad connector cascade bricks the whole diagram open.
- validateModelItem is an intentional no-op and validateView has no checks for layerId liveness, duplicate ids, tile-coordinate sanity, or label/textBox refs — schema (zod) checks shape only, so a model with two items sharing an id or a layerId pointing nowhere loads clean and only breaks later in by-id lookups (getItemByIdOrThrow picks the first match).
- Clipboard holds live references into the immer store; safe only because immer freezes state — any code path that produces unfrozen state (the batchUpdate* structural copies produce PLAIN unfrozen objects that enter the store!) makes copied payloads mutable-aliased to live state: a post-copy drag of the original then mutates what paste will insert.
- Selection dangling refs: only handleCut and load(!preserveViewport) clear selection; deletions via other paths (layer panel, undo of a create) leave selectedIds/itemControls pointing at dead ids — panel 'open but blank' regression class explicitly noted in the load path, but undo/redo never touches selection at all.
- useDirtyTracker: the 100ms post-ready window swallows a genuinely fast first edit (not dirty → close-tab data loss), and on re-load (isReady toggling) the previous subscription is only released via cleanupRef at UNMOUNT — a second load stacks subscriptions and the effect's timer-clear cleanup does not unsubscribe an already-registered listener.
- notification is a single slot with no queue: computePathsAsync progress toasts, paste success, and cut toasts overwrite each other — a large paste's 'routing X%' can bury an error notification from a concurrent failed load.
- uiState.view / previewLayerOverrides / editingTextBoxId consistency depends on every mutation path remembering to reset them (setView, setEditorMode, canvasResetForAnnotation each hand-roll subsets) — e.g. deleteLayer in the model never clears a previewLayerOverrides.hiddenLayerIds/soloLayerId entry for the deleted layer id (only setView/setEditorMode do), so a stale solo id can hide everything until the next view switch.

## Product questions (SUSPECT verdicts)

**Next:** area closed 2026-07-29 — all 15 proposed hypotheses resolved (12 BUG, 0 SUSPECT, 3 FALSIFIED), nothing DEFERRED. The dominant finding is a *class*, not a list: **the model has reference-integrity checks but no identity- or range-integrity checks.** Across E2-E4 the same hole produced duplicate ids (CLIP-01), duplicate anchor ids (SCN-03), dangling layer refs (RED-03/SCN-14), unknown icon refs (CLIP-14), unbounded tiles (CLIP-15), colliding layer `order` (RED-04/05) and duplicate page names (SCN-13). One `validateModel` pass covering identity + ranges would close most of them, and the write sites need the same ranges the schema declares (CLIP-13). Good news for later waves: the clipboard's *field fidelity* is solid — the ADR 0023 trio and ADR 0044 `iconScale` both round-trip intact (CLIP-11/12), and store state is frozen on every write path (CLIP-07).
