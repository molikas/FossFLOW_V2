## Seed seams (2026-07-29 mapping — starting points, not a ceiling)

- Second finger landing during an 'item' drag ends the drag by forwarding 'mouseup' with the SECOND pointer's clientX/Y (useInteractionManager.ts:1107) — the node commits at the new finger's projected tile, not where the dragging finger left it.
- Long-press → 'menu' phase after an 'item' down: the earlier forwarded mousedown left Cursor's mode.mousedownItem AND uiState.mouse.mousedown populated, and phase 'menu' never forwards a matching mouseup — Cursor.entry re-runs mousedown when mousedownItem is set (Cursor.ts:580-587), so stale press bookkeeping can bleed into the next gesture/mode transition.
- suppressLongPressGestureEnd installs capture-phase window listeners that preventDefault ANY cancelable touchend and swallow mousedown/click on .MuiBackdrop-root for up to 700ms — a deliberate fast tap-away to dismiss the menu inside that window is eaten; cleanup only on the first click or the timer.
- Pen hover parity: onPointerMove routes pen to onTouchPointerMove, which early-returns when the pointer isn't in ts.pointers (no press) — so pen hover produces no hover cursor, no hoveredItem outline, and stale uiState.mouse until a press; mouse gets all of these.
- 'palette' phase drop test is a raw getBoundingClientRect containment on rendererEl (lines 1344-1351, 1393-1399) — panels/docks that OVERLAY the renderer are inside that rect, so a touch drag from the Elements panel released over another panel still places the icon at the panel-occluded tile; the pointercancel variant (line 1388) has the same hole.
- Auto-lasso (hold on empty): forwards mousedown from the STALE captured down event `e` inside the setTimeout closure (startLongPress line 1086-1087) and flips phase to 'item'; its commit path races Lasso.mouseup's own setMode-to-CURSOR — two setMode(CURSOR) writes where the second stomps mousedownItem written by the first.
- Double-tap bookkeeping (lastTapTime/lastTapItem) is reset only on specific branches of onTouchPointerUp — a pointercancel between taps does not reset it, so a tap, app-switch (cancel), and tap on the same item within 300ms can spuriously open the details panel.
- Touch pointerdown decides 'item' vs 'pan-pending' via getItemAtTile WITHOUT the ADR-0023 point argument (line 1166) — an off-grid node's drawn body that no longer overlaps its integer tile hit-tests differently under a finger than under the mouse (Cursor paths pass cursorCanvasPoint), so touch may pan where mouse would drag the node, and vice versa.
- pinch math anchors the world point under the OLD centroid — it reads uiState.zoom/scroll per RAF frame while setZoom+setScroll land as two separate store writes; any other subscriber writing scroll between frames (e.g. a keyboard pan) shears the anchor.
- (mapper note) The forwarded compat events carry button:0 and target = interactions box (or the real anchor element for reconnect), so every mode sees a legitimate mouse gesture; pointerTypeRef is the only device-class channel and is mutated by ANY window pointer event, including ones over panels.
