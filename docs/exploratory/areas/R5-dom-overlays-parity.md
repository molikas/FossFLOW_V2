# R5 — DOM overlays & presentation parity (labels, hit proxies, grid, compositor)

**Status:** DONE · **Counted hypotheses:** 13 / 10 · **Bugs:** 7 · **Hypothesis ID prefix:** `OVL-`

*13 counted (7 BUG, 6 FALSIFIED); OVL-09 and OVL-11 are DEFERRED with reasons in their rows. The 7 bugs land in 7 known_issues entries. Four of them are the SAME sibling pair drifting four different ways: `LabelHitLayer` (floating Labels) has the lock gate, the counter-scale and the view-mode branch that `NodeLabelHitLayer` (node names) lacks — see the standing thread below.*

**Scope:** The DOM half of every GPU-drawn thing: Label.tsx renders the selected node's chip + dotted stalk with signed labelHeight placement (ADR 0024) and the label-as-handle vertical drag (window pointer listeners, 4px slop); ExpandableLabel adds the ADR-0015 counter-scale CSS var. NodeLabelHitLayer/LabelHitLayer are invisible SceneLayer divs sized by re-measuring the chip so canvas-drawn labels stay draggable/selectable. Grid paints the tile background purely via CSS background-size/position math per scroll/zoom write. IsoTileArea projects a tile range to an SVG rect through useIsoProjection (with the half-stroke inset). CanvasCompositorOverlay is the permanent full-area SVG that forces Chrome to recomposite the stacked WebGL canvases. UiOverlay hosts screen-space chrome, placement ghosts, and dialogs. useImageAspect caches icon aspect ratios for the ADR-0044 selection box. labelScale.computeLabelCounterScale is the shared pure math both CSS (--axoview-label-scale) and the GL u_counterScale uniform consume.

## Seed seams (2026-07-29 mapping — starting points, not a ceiling)

- Chip measurement is triplicated: NodesCanvas.measureNodeLabel (theme-derived padX/padY, honours bold 700/italic), NodeLabelHitLayer.measureNameChip (HARDCODED pad 12/8, max 250, always weight 600, ignores bold/italic/labelFontSize nuances), and Label.tsx's live DOM layout — bold or italic node names get hit boxes measurably narrower/wider than the drawn chip, and a theme spacing retune desyncs only the hit layer.
- Counter-scale parity: DOM scales about a flipped transform-origin (placement.transformOrigin, so the stalk attachment stays fixed) while the GL vertex shader scales LOCAL geometry about the instance anchor — the same label can shift its attachment by a few px when promoted between GPU bulk and DOM overlay at low zoom with readableLabels on.
- Grid is an entirely separate projection implementation (CSS background math: iso `backgroundSize h*2` + `+tileW/2` phase, 2D `-tilePx/2` centre alignment) — it must stay in lock-step with getTilePosition; fractional-zoom px rounding of background-position drifts grid lines against GL content, and the iso branch bakes in the specific two-row SVG asset layout.
- Label drag installs window-level pointermove/up/cancel listeners on pointerdown BEFORE slop is exceeded — the unmount safety-net effect removes them, but a mid-drag promotion/demotion (label unmounts because hybridIds changed) drops the gesture; interaction between this and NodeLabelHitLayer's parallel drag path (labelDrag store) is a two-owner seam.
- useImageAspect: no decode gate, no onerror — a failed icon URL leaves aspect at 1 permanently (never retried, cached miss), so the ADR-0044 selection outline height disagrees with the GL icon drawn via iconHeight(naturalHeight/naturalWidth); the two aspect sources can also disagree transiently (aspectCache empty until load, GL waits for decode).
- IsoTileArea's half-stroke inset (SVG) and RectanglesCanvas' fill inset (analytic AA) are the same rule implemented twice — retuning one side reintroduces either the clipped-border or the missing-bottom-border bug the comments document.
- CanvasCompositorOverlay is an empirically-found Chrome compositing workaround (zIndex 6, mounted only when editorMode !== NON_INTERACTIVE) — nothing asserts its presence; removing it, changing its z-index, or gating it differently resurrects the stale-blank-strip artifact only on specific GPUs (invisible to CI and to most dev machines).
- UiOverlay's PlacementGhostLayer computes getTilePosition inline per hover tile in a SceneLayer — a ghost is another independent consumer of the projection; mode-specific gating (`connectorArmed` reads mode fields via casts) can drift from the real interaction reducer's state shape.
- (mapper note) This area is where SVG/DOM and WebGL substrates must agree pixel-for-pixel. Most reported 'label jumps / wrong hit box / grid misaligned' bugs land here rather than in the GL code itself.

## Standing thread this area contributes

**The two label hit-proxy layers are one component written twice, and only one of
them is maintained.** `LabelHitLayer` (floating Labels) and `NodeLabelHitLayer`
(node names) do the same job — an invisible DOM div sized by re-measuring a chip
the GPU drew — and every improvement made to the first has been missed by the
second: the `lockedIds` gate (OVL-13), the ADR-0015 counter-scale (OVL-12), the
`EXPLORABLE_READONLY` hover branch (OVL-06), and, latently, the font-weight term
in its measurement (OVL-01, currently 0px in the shipped font stack). Both also
publish the SAME `data-axoview-id="canvas-label-hit"` and `data-label-hit-id`
attributes, so nothing — not a test, not a selector — can tell them apart except
by entity id. Any area that touches a label affordance should diff the pair
rather than test one; the durable fix is to make them one component with an
entity-kind prop.

**Falsified, and worth knowing:** the Grid's CSS-background projection stays in
lock-step with `getTilePosition` across resize and fractional zoom (OVL-04/05),
`CanvasCompositorOverlay`'s three load-bearing properties all hold (OVL-08), and
a label drag survives its proxy layer disappearing mid-gesture because the
gesture is owned by window listeners and the layer merely returns null rather
than unmounting (OVL-07).

**Next:** area DONE. R1–R5 close the rendering block; the app-shell block (A1) is next in wave order. Carry the two-hit-proxy-layers thread and the ADR-0023 offset-omission cluster (OVL-10 was its eighth member) forward.
