## Standing thread this area adds

**F-c. Bulk styling is representative-in / everyone-out.** The strip reads ONE
member (`sel = bulk.ids[0]`) and writes the derived value to all of them. That
is right for an absolute value (a colour, a size) and wrong for anything
derived: a toggle's DIRECTION comes from the representative (STYL-02, STYL-06),
and a toggle's PAYLOAD is the representative's whole field group (STYL-01).
The relative font-size stepper is the one control that reads each target's own
value — it is the shape the others want. Whenever an area finds a
fan-out, ask whether the value being fanned out was derived from one member.

## Product questions (SUSPECT verdicts)

| ID | Question | Recommendation |
|----|----------|----------------|
| STYL-02 | Should a mixed multi-selection show an indeterminate format state, and should one press APPLY rather than clear? | **Yes to both.** Today the button shows the representative's value (`aria-pressed="true"` for `[bold, plain]`) and one press clears bold everywhere. Word, Docs, Figma, Slides and Lucid all render mixed as indeterminate and treat the first press as "apply to all". Cheapest coherent fix: derive the pressed state as `all ? 'on' : some ? 'mixed' : 'off'` and send `next = !all` instead of `!representative` — which also fixes STYL-06's text-box path, since both read the same `formatValue` |
| STYL-03 | Which representation is "no colour" — the string `'transparent'` or an absent field? | **Absent, everywhere except where absent already means something else.** Rectangle fill and rectangle border write the sentinel; label background, text-box background and text-box border delete the field. Both work today because `ColorPickerBody` understands both and both render as no-fill — but the rectangle BORDER genuinely needs the sentinel (absent derives a stroke, which `absentIsNoColor={false}` correctly encodes), so the rule is not "always absent". Write it down in ADR 0039 and make rectangle FILL match its siblings (absent), leaving the border sentinel as the documented exception |
| STYL-08 | Should the bulk representative be the first selected item, or something stable? | **Something stable, or nothing.** `bulk.ids[0]` is `selectedIds[0]`, which for a lasso is scene order and for Ctrl+A is array order — so the values the strip displays for one selection are not predictable, and with STYL-01/02 unfixed they decide what gets written. If STYL-02's all/some/none derivation lands, the representative stops mattering for toggles; for the remaining absolute controls, showing "mixed" instead of one member's value is the honest display |

> **CLOSED 2026-07-30 — owner decisions** ([DECISIONS.md](../DECISIONS.md)): STYL-02 — indeterminate mixed state + first press applies to all (`next = !all`); STYL-03 — absent-is-no-colour is the rule, rectangle fill migrates, rectangle border keeps the sentinel as the documented ADR 0039 exception; STYL-08 — heterogeneous absolute values display "Mixed", never the representative's value.
