# ADR 0048 — Imported Image Asset Pipeline (crop, matte, encode)

**Status:** Proposed
**Date:** 2026-08-10
**Supersedes:** none (replaces the *undocumented* inline resize in [IconSelectionControls.tsx](../../packages/axoview-lib/src/components/ItemControls/IconSelectionControls/IconSelectionControls.tsx) and [ElementsPanel.tsx](../../packages/axoview-lib/src/components/LeftDock/ElementsPanel.tsx), which no ADR ever covered)
**Superseded by:** none
**Related:** [ADR 0049](0049-asset-store-and-reference-model.md) (where the bytes live), [ADR 0002](0002-icon-catalog-merge-on-load.md) / [ADR 0003](0003-session-storage-lean-icon-save.md) (catalog merge + lean save), [ADR 0044](0044-on-canvas-icon-resize.md) (per-node `iconScale`), [ADR 0038](0038-webgl-instanced-render-substrate.md) (the atlas that consumes the output)

## Context

Importing a raster icon today runs a single hard-coded transform, duplicated
verbatim in two components:

```ts
const TARGET = 128;                       // square box, aspect-fit
ctx.imageSmoothingQuality = 'high';
ctx.drawImage(img, x, y, w, h);           // ONE step, whatever the ratio
resolve(canvas.toDataURL('image/png'));   // PNG, always
```

- `handleFileSelect` in [IconSelectionControls.tsx](../../packages/axoview-lib/src/components/ItemControls/IconSelectionControls/IconSelectionControls.tsx)
- `handleImportConfirm` in [ElementsPanel.tsx](../../packages/axoview-lib/src/components/LeftDock/ElementsPanel.tsx)

Measured against a real 1536×1024 source, this loses quality three times over:

1. **A 12:1 downscale in one `drawImage`.** `imageSmoothingQuality: 'high'` is a
   small-kernel filter; at 12:1 it undersamples rather than averaging, so fine
   detail aliases instead of resolving. Irreversible — the source is discarded.
2. **The result is then magnified back up.** The on-canvas icon quad is
   `PROJ_W * 0.8 * scale` = 113 CSS px (`createNodeEmitter` in [nodeEmitter.ts](../../packages/axoview-lib/src/webgl/scene/nodeEmitter.ts)),
   rendered at `zoom * dpr` (the `b.render(…)` call in [SceneCanvas.tsx](../../packages/axoview-lib/src/components/SceneLayers/SceneCanvas.tsx)).
   At dpr 2 / zoom 1 that is **226 device px sampled from a 128-texel texture —
   1.8× magnification**; at zoom 2, 3.5×. The softness users report is
   upscaling, not compression.
3. **The renderer already allows 256.** `ICON_ATLAS_CAP = 256` in
   [SceneCanvas.tsx](../../packages/axoview-lib/src/components/SceneLayers/SceneCanvas.tsx).
   The import stage discards resolution the GPU path was built to accept.

Two further defects in the same code:

- **Square letterboxing.** A 3:2 source is padded into a 128×128 box, so the
  subject fills 128×85 of it and renders at ~75 px inside a 113 px slot —
  smaller than intended, with a third of the texels spent on transparency.
- **A dead pre-scale.** `const [iconScale, _setIconScale] = useState(100)` in
  [IconSelectionControls.tsx](../../packages/axoview-lib/src/components/ItemControls/IconSelectionControls/IconSelectionControls.tsx)
  bakes a scale factor into the raster. The setter is never called (hence the
  underscore), and [ADR 0044](0044-on-canvas-icon-resize.md) since made scaling
  a per-node, non-destructive property. It is dead weight that can only lose data.

**What the source images actually look like.** The driving use case is art
generated by an image model and pasted straight in. Such images are **rectangular
frames with a baked-in background** — a grey studio gradient, a dark vignette,
black corners — not transparent sprites. Cropping alone does not fix this: a
tile with black corners tiles into a visible grid of dark seams. **Background
removal is not a nice-to-have here; without it the imported asset is unusable as
a sprite.** No current code does any of it.

## Decision

Replace both inline transforms with **one shared, testable pipeline module**
plus **one import dialog** that previews every stage. The pipeline is a pure
function over an `ImageBitmap`; the dialog is its only UI.

### 1. The stages, in order

```
decode → auto-crop → user crop/rotate → matte (background removal)
       → resolution ladder (step-halved) → encode → hand off to ADR 0049
```

Each stage is individually skippable and each is independently unit-testable
against a fixture bitmap. The dialog shows the running result after every stage.

### 2. Auto-crop to content

Scan the alpha channel (or, after matting, the matte) for the tight bounding box
of non-background pixels; crop to it with a configurable margin (default 2 px).
This is what removes the letterboxing problem at its root — **the stored asset's
aspect ratio is the subject's aspect ratio**, never a padded square.

### 3. Matte — corner-seeded flood fill

The default background remover: flood-fill inward from all four corners in
Lab-ish space with a user-adjustable tolerance, then feather the resulting
alpha edge by 1 px to avoid a hard fringe. The dialog offers:

- **tolerance** slider (default tuned so a flat or gently-graded backdrop clears
  while the subject survives),
- **on/off** — flat vector logos that already have alpha must not be touched,
- a checkerboard preview so the user sees exactly what became transparent.

This is deliberately **not** a general matting model. It handles the vignette /
studio-gradient case, which is the case we have. Hair-fine edges and
subject-coloured backgrounds are out of scope; the user's fallback is to supply
an image with real alpha.

> TODO: does the tolerance default need to differ for `node` vs `tile` assets? A
> tile is cropped to a filled quad and may legitimately reach its own edge, where
> corner-seeding is exactly wrong. Decide with real tilesets in hand.

### 4. Resolution ladder — step-halved, never one jump

Downscale by repeated halving (1536 → 768 → 384 → **256**), each step a 2:1
`drawImage`, because a 2:1 step is inside the filter kernel and therefore
behaves like a proper box filter. The last step may be fractional.

**Target long-edge: 256 px**, matching `ICON_ATLAS_CAP` exactly. Chosen because
it is the largest size the render path can currently sample, so it is the
largest size that buys anything. Raising both together is a follow-up gated on
atlas-pressure measurement, not part of this ADR.

> TODO: 256 leaves the icon soft above ~1.1× zoom on a 2-dpr display. Raising
> `ICON_ATLAS_CAP` to 512 costs 4× atlas area per icon against a 4096² atlas on
> dpr≥2 devices (~60 icons). Measure before deciding; do not raise one without
> the other, or the extra bytes are stored and then thrown away by `putIcon`.

### 5. Encode — WebP, with a PNG fallback

`canvas.toDataURL('image/webp', q)` (or `toBlob`), falling back to PNG when the
browser cannot encode WebP (feature-detected by encoding a 1×1 and checking the
returned MIME type — Safari <16.4).

Users will overwhelmingly supply PNG; **PNG is the input format, WebP is the
storage format.** For rendered/photographic art WebP is 3–5× smaller at equal
quality and keeps alpha, so a 256 px WebP costs *less* than today's 128 px PNG
while carrying 4× the pixels. Quality defaults to 0.85, lossless for images
whose colour count falls under a flat-art threshold.

### 6. One module, one dialog — the duplication ends

- Pipeline: `packages/axoview-lib/src/utils/imageImport/` (pure, no React).
- Dialog: a new `ImportAssetDialog` replacing `ImportIconsDialog`.
- Both current call sites import the module. **Neither keeps a local resize.**

The existing [`ImportIconsDialog.tsx`](../../packages/axoview-lib/src/components/LeftDock/ImportIconsDialog.tsx)
is **deleted**, not left beside the new one: its only control (the isometric
checkbox) is absorbed as one field of the new dialog. Its e2e hook
`dialog-import-icons-confirm` must be re-pointed, not orphaned
(`packages/axoview-e2e/pom/DialogsPOM.ts`).

The dead `iconScale` pre-scale (§Context) is **removed**. Sizing is ADR 0044's
per-node `iconScale`, which is non-destructive and already shipped.

### 7. Asset kind — a tile is not a node icon

The pipeline tags its output `kind: 'node' | 'tile'`, chosen in the dialog.
This is **not** the same axis as `isIsometric`:

- `isIsometric` says *"the renderer already sheared this art; do not shear it
  again"* — a projection property.
- `kind` says *what the asset may be placed as* — a node, or a terrain cell
  ([ADR 0050](0050-terrain-paint-layer.md)).

Overloading `isIsometric` to mean both would break the moment a flat-drawn tile
or an isometric node icon appears.

**Multi-cell art is sliced here, at import.** A `tile` asset declares a
`tileFootprint` (how many grid cells the art spans); the pipeline cuts it into
**unit tiles**, which are what the store and the terrain model ever see
([ADR 0050](0050-terrain-paint-layer.md) §4 keeps the cell field strictly 1×1).
The brush reassembles them as a multi-tile stamp. Slicing at import is what
keeps painting, undo, culling, and serialisation ignorant of multi-cell art —
the complexity lands once, here, instead of in every consumer.

Assets also carry an optional `group` ([ADR 0049](0049-asset-store-and-reference-model.md) §13),
set in this dialog — organisation metadata only, never part of identity.

## Consequences

**Positive:**

- The stored asset is 4× the pixels at ~1/4 the bytes of today's output — the
  quality and the storage complaint are answered by the same change.
- Auto-crop removes the letterbox, so non-square art renders at its intended
  on-canvas size for the first time.
- Matting is what makes model-generated art directly usable; without it the
  whole "paste in what you generated" workflow does not actually work.
- One tested module replaces two divergent copies; the resize becomes
  unit-testable, which it has never been.

**Negative / risks:**

- **The import dialog grows from a checkbox to a real editor** (crop handles,
  tolerance slider, preview). That is a genuine UI surface with keyboard and
  touch obligations ([ux-principles](../guidelines/ux-principles.md) §4, §11) —
  the largest cost in this ADR.
- **WebP output is opaque to users** who expect the PNG they uploaded. The
  dialog must state the output format and size.
- **Matting will sometimes be wrong** (subject-coloured background). Mitigated
  by on/off plus live preview — never applied silently.
- **`ICON_COMPARE_FIELDS` drift.** That list in [leanSave.ts](../../packages/axoview-lib/src/utils/leanSave.ts)
  holds `name, url, collection, isIsometric` and **already omits `scale`**
  (added by ADR 0044) — so an icon overridden only by `scale` is treated as a
  pure duplicate and stripped, losing the override on load. Every field this
  arc adds — `kind`, `tileFootprint`, and `group`
  ([ADR 0049](0049-asset-store-and-reference-model.md) §13) — inherits that bug
  unless the list is fixed in the same wave. **Fixing `scale` is in scope here.**
- Re-importing does not retroactively improve already-imported 128 px assets.
  A re-import path is out of scope; originals are not retained (see ADR 0049).

## Implementation notes (non-binding)

- `createImageBitmap` for decode; `OffscreenCanvas` where available, falling
  back to a detached `<canvas>`. Avoid `createImageBitmap`'s `resizeQuality`
  option — Safari support is unreliable; the manual halving ladder is portable.
- The flood fill wants a scanline/queue implementation over a `Uint8ClampedArray`,
  not per-pixel recursion — a 1536×1024 source is 1.5 M pixels.
- Feature-detect WebP once per session and memoize.
- Fixture bitmaps for the unit tests: one vignetted render, one flat logo with
  real alpha, one already-square icon, one extreme-aspect banner.

## Acceptance criteria

- **Unit test:** a 1536×1024 fixture through the pipeline yields a bitmap whose
  long edge is 256 and whose aspect ratio equals the *cropped subject's*, not 1:1.
- **Unit test:** the halving ladder produces measurably more retained
  high-frequency detail than a single `drawImage` at the same final size
  (compare against a reference box-filtered downscale; assert lower error).
- **Unit test:** corner-seeded matte on the vignette fixture clears all four
  corners to `alpha === 0` and leaves the subject's centroid at `alpha === 255`.
- **Unit test:** matte **off** leaves an alpha-bearing flat-logo fixture
  byte-identical through the matte stage.
- **Unit test:** WebP-unavailable (stubbed `toDataURL` returning `image/png`)
  falls back to PNG and still produces a valid decodable image.
- **Unit test:** `stripDefaultIcons` preserves an icon that differs from the
  catalog only by `scale` (the current bug), and likewise by `kind`.
- **Manual verification:** import the ship render; at 100 % zoom on a 2-dpr
  display it is visibly sharper than the same file imported before this change,
  and the grass tile shows no dark corner seam when painted adjacent to itself.
